## Deslop Applied

- **Deleted `app/routes/__init__.py`** (tracked, 1 line: `# Routes package`). No importer exists:
  `git grep -n "from app.routes\|import routes"` and `grep -rn "routes" --include=*.py app cli.py tests`
  only match `App._setup_routes` (unrelated). Remaining content of `app/routes/` was untracked
  `__pycache__`, removed with it. Observable effect: `import app.routes` no longer resolves; nothing in
  the repo or its tests did that.
- **`cli.py`: 7 redundant `f""` prefixes removed** (ruff `F541`, lines 144, 226, 298, 377, 416, 437, 532).
  The literals contain no `{...}` placeholders, so the resulting strings are byte-identical.
- **`cli.py:504`: dropped a function-local `import subprocess`.** `subprocess` is already imported at
  module scope (`cli.py:29`). Same module object; no import-order or shadowing change (found with an AST
  scan; ruff does not flag it).
- **`app/pipeline.py:310`: dropped a function-local `from app.quantization import BitLinear`.** `BitLinear`
  is already imported at `app/pipeline.py:33`; removing an exact duplicate cannot change resolution.
- Behaviour-preservation evidence: `uv run pytest -q` 134 → 138 passed (the delta is the 4 new CORS tests),
  `uv run ruff check app cli.py tests scripts` → *All checks passed!*, `python -m compileall` clean,
  and the bandit diff shows only line-number shifts plus the intended rule changes.

**Deliberately not deslopped** (behaviour or public-surface risk; recorded instead): the duplicate
`pack_ternary_weights`/`unpack_ternary_weights` in `app/quantization/utils.py` (public names, different
signature from the exported `packing.py` pair), the four unreferenced fixtures in `tests/conftest.py`,
`print`→`logging` migration in library modules, the 5× duplicated ffmpeg re-encode blocks, the duplicated
`echo`/comment banner line in `install.sh`, and the unused `ProcessRequest`/`GenerateRequest` models in
`app/main.py` (they match the JSON API documented in the README — review finding #4).

## Full Review Findings

Ranked by impact (read-only phase; no code changed here).

1. **FLUX models cannot work with the pinned diffusers (high).** `pyproject.toml` pins `diffusers==0.24.0`
   (same in `requirements.txt`), but `app/pipeline.py:279,308,416` import `Flux2KleinPipeline` /
   `Flux2Transformer2DModel`, and `app/multistyle.py:255` force-loads `flux2-klein`. Verified in this venv:
   `diffusers 0.24.0` → `ImportError: cannot import name 'Flux2KleinPipeline'`. Tests mock `diffusers`, so
   CI stays green while every FLUX / multi-style run fails at load time. Fix: declare the diffusers version
   that actually provides the FLUX.2 classes (README mentions installing diffusers from `main`) or fail fast
   at startup with a clear message.
2. **The app cannot be imported from a clean install (high).** `streamdiffusion` is declared nowhere
   (`requirements.txt` keeps it as a *comment* pointing at the upstream GitHub URL; `pyproject.toml` and
   `uv.lock` have no entry) and the tracked fork in `StreamDiffusion/` is never installed.
   `uv run python -c "import app.main"` → `ModuleNotFoundError: No module named 'streamdiffusion'`.
   `install.sh` advertises a one-command install but only installs `requirements.txt`. The test suite hides
   this with `sys.modules.setdefault("streamdiffusion", MagicMock())` (`tests/conftest.py:20`,
   `tests/test_api.py:23`), so the real wrapper wiring is never exercised.
3. **Undeclared runtime dependency (`rich`).** `cli.py:38` imports `rich`, which appears in `uv.lock` only
   as a dependency of dev tools (`bandit` at `uv.lock:72`, `pip-audit` at `uv.lock:945`). A runtime-only
   install (`uv sync --no-dev`, `pip install -r requirements.txt`) breaks `python cli.py`.
4. **Documented API contract does not match the implementation.** `README.md:166` and `README.md:233` show
   JSON bodies for `/api/generate` and `/api/process`, but both endpoints declare `Form(...)`
   (`app/main.py:345-349`, `app/main.py:378-381`) → the documented `curl` calls return 422. The unused
   pydantic models `ProcessRequest` (`app/main.py:194`) and `GenerateRequest` (`app/main.py:201`) match the
   JSON contract, suggesting the endpoints were meant to accept JSON. Decision needed: wire them up or fix
   the README.
5. **No authn/authz plus the `0.0.0.0` default bind** (details in Security Findings). The README presents
   remote binding as supported, so this is a deployment trap rather than a theoretical one.
6. **`torch.load` without `weights_only=True`** — see Security Findings; also a footgun for anyone pointing
   `quantized_path` at weights downloaded from a hub.
7. **Duplicated ffmpeg H.264 re-encode logic with divergent failure handling.** `cli.py:207-224`,
   `cli.py:360-375`, `cli.py:503-519`, `app/video_processor.py:96-120`, `app/multistyle.py:299-320`.
   `video_processor`/`multistyle` write a sibling file and do an atomic `os.replace`; `cli.py` does
   `os.remove`/`os.rename` with a "keep the temp file" fallback. One helper would remove ~80 lines, but the
   failure semantics genuinely differ, so it was left alone.
8. **Copy-pasted error handling and print-based logging in library code.** `app/pipeline.py` repeats
   `except Exception as e: print(...); import traceback; traceback.print_exc()` at lines 200, 272, 297, 403,
   461, 609 (`app/monarchrt_pipeline.py:151,195,247` does the same), and `app/pipeline.py` has 20+ `print()`
   calls while `app/main.py` uses `logging`. Server logs therefore lose levels/timestamps for model loading
   and job failures; `app/video_processor.py:409` prints a traceback from a worker thread.
9. **Dead duplicated quantization API.** `app/quantization/utils.py:182` and `:226` define
   `pack_ternary_weights`/`unpack_ternary_weights` with a different return signature than
   `app/quantization/packing.py:16`/`:67` (the pair exported by `app/quantization/__init__.py` and used by
   `tests/test_quantization.py`). Nothing imports the `utils.py` versions. The package docstring also
   advertises `load_quantized_unet` (`app/quantization/__init__.py:11`) while the export is
   `load_quantized_model`.
10. **Test-coverage gaps.** 2,061 test LOC against 4,691 app LOC, but nothing covers `cli.py`,
    `app/multistyle.py` (Ollama/LLaVA path), `app/quantization/kernels/ternary_matmul.py` (Triton), or the
    FLUX/MonarchRT loaders against real libraries. `tests/test_video_processor.py:180` hardcodes
    `/tmp/test_outputs`. The upload-limit test only asserts `status in (200, 400, 413)`, so it cannot detect
    a missing size cap.
11. **Stale user-facing message.** `app/pipeline.py:318` tells users to run `scripts/quantize_flux.py`, which
    does not exist (the real script is `scripts/quantize_model.py`).
12. **Unused test fixtures.** `tests/conftest.py:28` (`tmp_dir`), `:96` (`dummy_pil_image`),
    `:132` (`mock_monarchrt_pipeline`), `:153` (`mock_torch_cuda`) are referenced nowhere in `tests/`.
13. **Container/ops hygiene.** Root `Dockerfile` builds only `StreamDiffusion/examples/screen/final_server.py`
    on `python:3.10-slim` (project requires ≥3.12), installs unpinned requirements, runs as root and has no
    `.dockerignore`; `tf-notebook.yaml` runs Jupyter as root with `fsGroup: 0`; `start.sh` hardcodes a conda
    env named `streamdiffusion`.
14. **Positive:** `scripts/verify.sh` is a real pre-handoff gate (compileall, pytest, frontend build,
    `npm audit`, `pip-audit`, bandit, whitespace checks); dependency and bandit scans are advisory by default,
    documented at `README.md:100-107`.

## Remaining Risks

- **Not verified end-to-end:** no live server run (blocked by the missing `streamdiffusion` package) and no
  real inference on any model. An A10 GPU is present, but exercising it needs ~3 GB of downloads plus
  Triton/TensorRT setup; the model paths are only covered by mocked tests.
- **`torch.load` hardening is documented, not applied** — it needs a checkpoint-holding environment to
  confirm `weights_only=True` does not break the real MonarchRT/quantized files (none exist here).
- **StreamDiffusion demo CORS and the `{@html}` model-card injection are documented only**, by choice:
  upstream-derived demo code, where a fork-local patch would diverge from upstream.
- **The new CORS default can break a deployment that serves the UI from a separate origin.** That is the
  intent of the change; `CORS_ORIGINS` (now documented in `README.md:378`) is the escape hatch. Anyone
  relying on the old wildcard must set it explicitly.
- **The `0.0.0.0` default bind and the absence of authn/authz are unchanged**; the API remains fully open to
  anyone who can reach the port.
- **Verification is Python-only.** `npm run build`, `npm audit` and `pip-audit` were not run (frontend
  untouched; network-dependent). `scripts/verify.sh` covers them, but its security checks are advisory
  (`VERIFY_SECURITY_STRICT=1` to enforce).
- **Review findings 1–4 are unresolved dependency/product issues** (diffusers pin, missing
  `streamdiffusion` declaration, undeclared `rich`, README-vs-`Form(...)` API contract). They need an owner
  decision rather than a drive-by patch.
